O problema

Você só descobre que quebrou depois

O ciclo real de quem escreve código — pessoa ou IA — é editar, editar, editar, e só então testar. Isso cobra dois preços.

01

Detecção tardia

Quando o teste enfim roda, já existem várias mudanças acumuladas. Isolar qual delas quebrou o quê vira arqueologia — e, com um agente de IA, ele já avançou meia dúzia de passos em cima de uma suposição errada.

editeditedit editedit testes ✗
02

Escopo subestimado

A ferramenta roda o teste do arquivo que mudou e para por aí. Mas login.ts quebrou — e quem acusa são os testes de header.ts e footer.ts, que ninguém rodou. A regressão passa.

login.test header.test footer.test layout.test

O diferencial

Você decide até onde propaga

Escolha a profundidade e veja, agora, o que aconteceria ao salvar login.ts. É a mesma busca em largura que roda no daemon.

    A regra que produz isso

    Dois consumidores, um só daemon

    Feito para a IA e para você

    Nenhuma ferramenta de watch foi desenhada para ser lida por um agente. Esta foi — sem abrir mão do painel visual no editor.

    Para o agente de IA

    Três níveis de esforço, do mais barato ao mais completo.

    1. Uma linha grepável. Todo lote termina com campos chave=valor. Um grep basta. 
      LIVETEST batch=batch-7 status=failed files=3 tests=12 passed=10 failed=2 skipped=0 duration=1.4s
    2. Um snapshot sempre atual. .livetest/status.json é escrito de forma atômica — nunca se lê um JSON pela metade.
    3. O histórico completo. .livetest/run.log em NDJSON, um evento por linha, com o motivo de cada teste ter rodado.

    Prefere controlar quando testar? livetest run devolve exit code 1 quando falha — encadeia direto em &&.

    Para você, no VSCode

    Árvore de arquivos com o status e o motivo de cada execução.

    ▾ src 1 com falha
    login.test.ts 2/2
    header.test.ts 0/1
    header renderiza
    footer.test.ts 1/1
    layout.test.ts
    header.test.ts por que rodou: header.ts importa login.ts (1 nível)

    A extensão não sobe o daemon sozinha: ela procura um em execução e, se não achar, mostra o botão de iniciar. A ação continua sendo sua.

    O que vem na caixa

    Pequeno no caminho, completo no essencial

    ◈

    Grafo de dependências de verdade

    JS/TS pela API do compilador TypeScript — resolve paths, baseUrl, index.* e o mapeamento ./x.js → ./x.ts. Python pelo módulo ast nativo, com imports relativos e absolutos.

    ⏱

    Debounce que não te trava

    Agrupa saves consecutivos por inatividade e por janela máxima. Uma sequência longa de edições nunca adia os testes para sempre — nem dispara a cada tecla.

    ⌁

    Transparência total

    Toda seleção vem com a cadeia de importação que a justifica. Não entendeu por que algo rodou? livetest why src/login.ts mostra o caminho inteiro.

    ⚑

    Degrada, não cai

    Python sumiu? Cai para análise por regex e avisa. Adapter quebrou? O arquivo roda isolado e o evento diz o que mudou. O daemon segue de pé.

    ⬡

    Adapters plugáveis

    Go, Rust, Java: implemente DependencyGraphAdapter e TestRunnerAdapter, ou use o adapter command e tenha watch, debounce e mapeamento sem escrever uma linha.

    ◱

    Independente de IDE

    O core roda 100% no terminal. A extensão é só uma camada de visualização — o fluxo com agente funciona com o editor fechado.

    Configuração

    Um arquivo. E ele é opcional.

    Sem nenhuma configuração, o daemon já funciona em projetos JS/TS ou Python com layout convencional. O arquivo existe para quando você quer controle fino.

    Começar

    Três comandos e acabou

    1. 1

      Instale como devDependency

      $ npm install --save-dev @livetest/cli
    2. 2

      Confira o ambiente

      $ npx livetest doctor

      Verifica configuração, globs observados, cobertura de testes e se os binários dos runners existem — antes de você perder tempo depurando silêncio.

    3. 3

      Deixe rodando

      $ npx livetest start

      Para um agente de IA, jogue em background e leia a linha LIVETEST ao fim de cada lote.

    Pare de descobrir a quebra no final

    Node 18.18+. Para Python, um interpretador 3.8+ no PATH. Nada além disso.

    npx livetest init && npx livetest start
